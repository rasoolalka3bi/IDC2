# تطبيق موظفي شركة الحفر العراقية (الإصدار 3.0.0)

إعادة تصميم كاملة لتطبيق IDC (الإصدار القديم 2.0.3) مبنية بـ Flutter، وتتصل بنفس خادم الشركة `idc-iq.net`.

## الشاشات
- تسجيل الدخول، استعادة كلمة المرور، الدخول بالبصمة، وضع تجريبي ببيانات وهمية.
- الرئيسية: صافي الراتب، ملخص الحضور والنقاط، الخدمات، آخر التبليغات.
- الراتب: اختيار الشهر والسنة، المدفوعات والاستقطاعات والمعلومات الأساسية، حفظ القصاصة PDF ومشاركتها.
- التبليغات والاستفسارات (مع الرد).
- حسابي: تغيير الصورة وكلمة المرور، البصمة، الوضع الليلي، التعليمات، تسجيل الخروج.
- الخدمات: الحضور، نقاط الإسكان، الدورات، كتب الشكر (بتصميم التطبيق)، والأرباح وقطع الأراضي والاستبيان والزمنيات (من صفحة خدمات الشركة).

## ما يحتاج تأكيدًا مع خادم الشركة
الكود الأصلي غير متوفر، لذلك استُنتجت عناوين الخادم وأسماء الحقول من ملف التطبيق القديم. كل ما يخص الاتصال موجود في ملفين فقط:
- `lib/data/api.dart`: العناوين وأسماء المعاملات المرسلة.
- `lib/data/models.dart`: قراءة الردود (تقبل أكثر من شكل).

خدمات الحضور والنقاط والدورات والتشكرات تأتي حاليًا من الخادم كصفحة ويب (`egate/home_page.php`)، فتُفتح داخل التطبيق بتنسيق قريب من تصميمه. عند توفير واجهة بيانات JSON لها تُربط بالشاشات الجاهزة في `lib/screens/services/` بتعديل `ApiRepository` فقط.

الإشعارات الفورية (Firebase) غير مفعلة لأنها تحتاج ملف `google-services.json` من حساب Firebase الخاص بالشركة. التطبيق يعرض عدد التبليغات غير المقروءة من الخادم عند فتحه.

## البناء
```bash
flutter pub get
flutter test
flutter build apk --release --split-per-abi
```
الملف الناتج في `build/app/outputs/flutter-apk/` (استخدم `app-arm64-v8a-release.apk` لمعظم الهواتف).

عند رفع المشروع إلى GitHub يبني ملف `.github/workflows/build-apk.yml` ملف APK تلقائيًا، ويمكن تنزيله من تبويب Actions.

معرّف التطبيق `com.idc.employee` مختلف عن التطبيق الرسمي (`com.idc.app`) لتجنب التعارض. لنشره كتحديث للتطبيق الرسمي يجب استخدام المعرّف الرسمي ومفتاح التوقيع الخاص بالشركة.
